# 窗口缩放与全屏切换时的白闪

DSH 在两个场景下会出现白色/浅色闪烁，均由 Chromium 渲染时序决定，无法消除：

## 1. 拖边框缩放窗口时的白带

**现象**：拖动窗口边框改变大小时，新露出的区域会闪一条白色/浅色带。

**根本原因**：
- 系统先改窗口尺寸（DWM 层面）
- Chromium 渲染进程要经过 `WM_SIZE → IPC → 布局 → 绘制 → 提交 → 合成` 才知道新尺寸
- 这几帧里窗口表面必须显示某个东西：上一帧的内容 + 一层底色
- **没有任何 API 能让内容和边框同步伸缩**

**为什么 Chrome/Edge 不白**：它们用原生边框，不走无边框窗口的这条合成路径。

**试过的 15 种方法，全部无效**：

| # | 假设 | 做法 | 结果 |
| --- | --- | --- | --- |
| 1 | CSS 层（壁纸 / tint / 预模糊） | 皮肤整个关掉再拖 | ❌ 还有 |
| 2 | `bottomRow` 露底 | 该行改透明 | ❌ 无关 |
| 3 | 根画布不透明底 | `html/body/#root` 改透明 | ❌ 无关 |
| 4 | 视口比窗口矮 | 拖动探针抓 40 帧尺寸 | ❌ 差值恒为 7–14px |
| 5 | 窗口底色 `backgroundColor` | 改 `#ccd8eeff`、做**红色实验** `#ff0000ff` | ❌ 窗口纯红、带子仍白 |
| 6 | DWM 亚克力材质 | 关掉 `backgroundMaterial` | ❌ 无关 |
| 7 | WM_ERASEBKGND（窗口类背景刷） | 开 `transparent: true` 变分层窗口 | ❌ 分层窗口不会被类背景刷擦，带子还在 |
| 8 | 透明窗口本身 | Electron 44 的透明 + 可缩放组合 | ❌ 能拖，带子照旧 |
| 9–12 | GPU 合成层 | `--enable-features=windows11-mica-titlebar` 等 4 条开关 | ❌ 全无效 |
| 13–14 | Chromium 默认底色 | `--default-background-color=ffccd8ee` / `00000000` | ❌ 全无效 |
| 15 | 内核通病 | 拖 Chrome / Edge 窗口 | ✅ **它们不白** → 不是内核通病，是 DSH 的窗口配置 |

**留下的缓解**（都在，默认开，外观页可关）：
- 拖动时壁纸换成纯色 `#ccd8ee`（和窗口底色同值，带子露出来颜色一致）
- 简化壁纸（砍三层光效，重绘更轻）
- 壁纸层 `will-change: transform`（缩放走图层变换）

## 2. 点全屏时的白框

**现象**：点右上角最大化按钮进入全屏时，窗口会闪一帧白色/浅色框。

**根本原因**：同拖边框，窗口从窗口态 → 全屏态的尺寸切换，中间那一帧 Chromium 不重绘，DWM 用窗口底色填充。

**不是回归**：这是全屏切换的既定现象，不是这次改动引入的。

**验证办法**（若将来需要确认 `backgroundColor` 是否参与）：
1. 改 asar 把 `backgroundColor` 改成纯红 `#ff0000ff`
2. 完全退出 DSH，重开
3. 点全屏，看那一帧是红还是白
   - 红 → `setBackgroundColor` 参与，需要改主进程加钩子
   - 白 → 和拖边框同理，不改代码

## 给未来的自己

**不要再试了。** 上面 15 条 + 透明窗口 + GPU 开关 + 默认底色已经覆盖：CSS、窗口底色、材质、擦除、透明窗口、GPU 合成、Chromium 默认底色。

剩下能做的只有：
- **牺牲功能**：禁止缩放（B3）、关掉系统实时缩放（`DragFullWindows=0`）
- **牺牲观感**：全屏玻璃 + 可拖动卡片（损失并排 + 复杂穿透判定）
- **改主进程**：加 `before-full-screen` 钩子，但需要 asar 等长替换 + 完全重启验证

这三条都不值。**这两条白闪是 Chromium + 无边框窗口的固有现象，所有同类应用都有（VS Code、Slack、Discord）**。它们不影响功能、不影响帧率、只在这两个动作时出现一两帧。

## 验证方式

- **不要用 Ctrl+R**——Windows 上没有绑定重载快捷键
- 渲染层改动：点「刷新与重启 → 刷新界面」
- 主进程/asar 改动：完全退出重开
