# 窗口缩放时的白带：排查记录

DSH 主窗口拖边框改大小时，新露出的区域会闪一条白色/浅色带。这份记录是完整排查过程，**结论是：在 Electron 44 + 无边框窗口上无法消除，不要再花时间试。**

## 一句话结论

那条带子是 **Chromium 渲染时序**和 **DSH 的无边框窗口配置**叠加的结果：

- 系统先改窗口尺寸，渲染进程要等 `WM_SIZE → IPC → 布局 → 绘制 → 提交 → 合成` 才知道新尺寸；
- 这几帧里窗口表面必须显示某个东西，于是露出上一帧 + 一层底色；
- Chrome / Edge 用**原生边框**，走的不是这条路径，所以它们不白，**只有 DSH 白**。

**没有任何 API 能让渲染进程和窗口边框同步伸缩**——这不是缺开关，是架构决定的。

## 试过什么、排除了什么

| # | 假设 | 做法 | 结果 |
| --- | --- | --- | --- |
| 1 | CSS 层（壁纸 / tint / 预模糊） | 把皮肤整个关掉再拖 | ❌ 还有 → 与皮肤无关 |
| 2 | `bottomRow` 露底 | 该行改透明 | ❌ 无关 |
| 3 | 根画布不透明底 `#f0f3fc` | `html/body/#root` 改透明 | ❌ 无关（实测带子 RGB(239,242,251) 与 #f0f3fc 接近只是巧合） |
| 4 | 视口比窗口矮 | resize 探针抓 40 帧 `innerHeight` / `outerHeight` / `frameH` | ❌ 差值恒为 7–14px，DOM 里没有空隙 |
| 5 | 窗口底色 `backgroundColor` | asar 补丁改 `#ccd8eeff`、再做**红色实验** `#ff0000ff` | ❌ 窗口纯红、带子仍白 → 与窗口底色完全无关 |
| 6 | DWM 亚克力材质 | 关掉 `backgroundMaterial` | ❌ 无关 |
| 7 | WM_ERASEBKGND（窗口类背景刷） | 开 `transparent: true` 变分层窗口 | ❌ 分层窗口不会被类背景刷擦，带子还在 |
| 8 | 透明窗口本身 | Electron 44 的透明 + 可缩放组合 | ❌ 能拖，带子照旧 |
| 9 | GPU 合成层 | `--enable-features=windows11-mica-titlebar` | ❌ |
| 10 | 同上 | `--use-angle=d3d9` | ❌ |
| 11 | 同上 | `--disable-gpu-compositing` | ❌ |
| 12 | 同上 | `--disable-direct-composition` | ❌ |
| 13 | Chromium 默认底色 | `--default-background-color=ffccd8ee` | ❌ |
| 14 | 同上 | `--default-background-color=00000000` | ❌ |
| 15 | 内核通病 | 拖 Chrome / Edge 窗口 | ✅ **它们不白** → 不是内核通病，是 DSH 的窗口配置 |

## 为什么改颜色治不好

带子的颜色**跟着页面内容走**：皮肤开着是浅蓝，皮肤关掉是白。而窗口底只有一个颜色、内容却是渐变，一条边对上另一条边必然对不上。这也是红色实验能一次排除「窗口底色」的原因。

## 留下的缓解（都在，默认开）

| 措施 | 代码 | 作用 |
| --- | --- | --- |
| B1 拖动时降级 | 外观页「拖动时降级」，`resizeDegrade: true` | 拖窗口时壁纸和预模糊层换成纯色 `#ccd8ee`（= 窗口底色），松手 150ms 恢复 |
| B6 简化壁纸 | 外观页「简化壁纸」，`simpleWallpaper: true` | 砍掉三层径向光斑，缩放重绘更轻 |
| B7 图层提升 | `#dsh-concierge-glass > div:first-child { will-change: transform }` | 缩放时走图层缩放，不重新栅格化渐变 |

三条叠加能把带子压到一两帧、且颜色与周围一致。

## 给未来的自己

- **不要再试了。** 上面 15 条已经覆盖：CSS、窗口底色、材质、擦除、透明窗口、GPU 合成、Chromium 默认底色。剩下能做的只有「禁止缩放窗口」（牺牲并排和拖拽）或「全屏玻璃 + 可拖动卡片」（牺牲穿透和并排），都不值。
- 想确认「是不是 DSH 特有」的最快办法：**拖一下 Chrome 的边框**。它不白，就说明不用再查内核。
- `scripts/patch-window-fallback.mjs` 里那套 asar 补丁**已还原**，只在需要做窗口级实验时再用；`--revert` 有版本校验，应用更新后不会把版本退回去。

## 验证方式

**不要用 Ctrl+R**——这个应用在 Windows 上没有绑定重载快捷键。要么点「刷新与重启 → 刷新界面」（渲染层改动），要么完全退出重开（主进程 / asar 改动）。
