# dsh-concierge

DeepSeek Harness 的维护中心：更新应用与插件、管理已装插件、盯着聊天性能。

设置 → 维护中心，六个标签页：**更新**、**插件**、**工具**、**性能**、**打字机**、**关于**。

## 功能

### 更新

- **应用本体**：读取桌面版 `resources/app-update.yml` 声明的更新源，与已装版本比较；只有桌面端自己报告有更新时才提供更新入口，走桌面壳原生更新流程。
- **插件**：npm 插件查镜像与插件管理器，GitHub 插件查 releases（没有 release 时退回 tags），本地插件看源目录版本或文件指纹。
- **一键更新 / 全部更新 / 自动更新**：完成后右上角弹提示，需要重启时按钮就是「重启应用」。
- **回退**：npm 插件可回退到镜像上任意历史版本，GitHub 插件可回退到任意 tag；失败自动装回原版本。

### 插件

- 列表、搜索、全部 / 可更新筛选；
- 每行可更新、回退、忽略该版本、启停、卸载、看更新内容、打开主页；
- 加载失败被自动禁用的插件会在顶部提示，可一键启用。

### 工具

- **GitHub 来源**：添加任意仓库并持续检测最新 release；未装的可以装，已装的可以重装；安装时把 HEAD 固定成完整 commit。
- **从 npm 安装**：填包名或 `包名@版本`。
- **GitHub Token**：状态标签 + 掩码显示 + 申请链接，额度从 60 次/小时提到 5000 次。
- **外观**：主题（跟随系统/浅色/深色）、皮肤（柔和/墨色/海洋/自定义）、品牌色、字号、代码字体。全部走官方主题服务：`setTheme` / `overrideTokens` / `adjustFontSizes` / `setFontFamily`，不注 CSS、不改官方 DOM。走官方主题 API（`theme.overrideTokens`），每个 token 给浅色/深色两份，换主题自动跟随，不注 CSS、不改官方 DOM，DSH 升级也不失效。默认关闭。
- **目录与配置**：打开插件目录 / 配置 / 安全模式目录。
- **自动安全模式**开关。

### 性能

- 帧率（5 秒平均，上限跟随屏幕刷新率）、消息行数、最近 10 秒长任务与累计阻塞、80 秒条形历史与峰值。
- **启动加速**：把应用目录、`~/.dsh`、插件目录加进 Windows Defender 排除项（弹一次 UAC）。
- **自动降级**：低于刷新率 50% 持续 3 秒进精简，回升到 65% 以上持续 5 秒恢复，15 秒冷却。
- **侧边栏收起优化**：侧边栏动画期间只重排可见消息行。
- **收起不做动画**：把 0.3 秒宽度过渡置零，收起只重排一次。
- **屏幕外行跳过**（默认开）：给聊天流每一行加 `content-visibility`，屏幕外的行不参与布局与绘制；同时兼容 dsh-better-sidebar 的文件树和任务树。
- **刷新率上限**：自动跟随屏幕，也可手动指定。

### 打字机

- **逐字显示**（默认关）：只作用于流式输出的那段文字，思考、工具调用、图片保持原生。
- **流式节流**（默认开，33ms）：把应用「每个 token 一次」的渲染合并，减少重绘。

### 关于

- 版本号、仓库链接、可折叠的更新日志（读仓库根的 `CHANGELOG.md`）。

## 安装

在 DSH 里打开 **插件 → 安装插件**，填入：

```
github:coldrainthreeautumnleaves/dsh-concierge
```

或者命令行：

```sh
dsh plugin --profile <profile> add github:coldrainthreeautumnleaves/dsh-concierge
```

安装后重启 DSH（Host 部分需要重启，客户端部分刷新页面即可）。

> 密钥怎么申请、安全模式怎么用，见 [docs/GUIDE.zh.md](docs/GUIDE.zh.md)。

## 安全模式

如果某个插件损坏、应用起不来，插件自己也没机会运行——所以启动时它会把脚本写到 `~/.dsh/update-center/`：

- `safe-launch.cmd` / `.vbs`：**自动版**，启动后观察 30 秒，崩溃就自动切安全模式重启；把桌面快捷方式指向它即可；
- `safe-mode.cmd` / `.vbs`：手动版，备份配置 → 只加载官方插件启动；
- `restore-mode.cmd` / `.vbs`：恢复配置并重启。

`.vbs` 是静默版：双击全程无命令窗口。脚本都要求应用已退出，不需要管理员权限。

## GitHub Token

工具页可以填一个 GitHub token：不带时 GitHub API 每小时 60 次（按 IP），带了是 5000 次（按账号）。存在 `~/.dsh/update-center/settings.json`，只读公开仓库的 token 就够；环境变量 `GITHUB_TOKEN` / `GH_TOKEN` 优先。

## 开发约定

**每次做功能前先上网深度搜索**：看官方/社区已经怎么做、有没有现成接口或已知坑，再动手。

**加功能前先核对三件事**：

1. **官方是否已经有**——先在设置页、内置插件列表、`app.asar` 里确认。官方已有的不重复造（例：官方「侧边卡片」内置后，再装一个接管侧边栏的插件只会更卡）。
2. **本插件是否已经实现**——先搜 `client.js` / `index.js` 里的文案、路由和开关，避免同一个功能两个入口。
3. **是否和已装插件冲突**——同类功能（侧边栏、输入区增强、消息渲染）先看它们占了哪个槽位、改了哪块 DOM。

**加完要验证**：真实环境跑一遍——接口返回、页面渲染、日志都对上，不能只靠语法检查通过就交付。

**排版规则**：带开关/选项的卡片一律排在所在页的最前面，信息类卡片（统计、来源列表、目录）排在后面。

## 发布流程

每次发版都做这四件事，缺一不可：

1. `package.json` 版本最后一位 +1；
2. `CHANGELOG.md` 顶部加一节；
3. **本 README 的简介与功能清单同步更新**；
4. 提交并推送。

## 要求

- DSH 0.2.1 及以上（`engines.dsh`）
- Node.js 22 及以上

## 开发

```sh
# 本地链接安装
dsh plugin --profile <profile> add link:<本仓库绝对路径>
```

改 `index.js` 后需要重启 DSH；改 `client.js` 后刷新页面。
