# 维护中心

设置 → 维护中心 分成五个标签页：**更新**（应用本体版本与更新、自动更新开关）、**插件**（已装插件列表、搜索、更新 / 回退 / 启停 / 卸载）、**工具**（安全开关在最上面，下面依次是 GitHub 来源、从 npm 安装、GitHub Token、目录与配置——所有输入框和「打开插件目录 / 打开配置 / 打开安全模式目录」都集中在这里）、**性能**（帧率、长任务与降级开关）、**打字机**（逐字显示、流式节流与速度）、**关于**（介绍、版本号、可折叠的更新日志）。

版本号规则：每次发版最后一位 +1（`0.1.1` → `0.1.2` → …），更新日志写在仓库根的 `CHANGELOG.md`，「关于」页直接从宿主读它和 `package.json`，不用改代码。

## 检查什么

- **应用本体**：读取桌面版安装目录 `resources` 下的 `app-update.yml`，按它声明的通用更新源（例如 `https://download.deepseek.com/dsh-desk/feeds/win-x64/nightly.yml`）取最新 `version`，与已安装版本比较。发现新版本时，桌面端卡片显示「重新检测 / 更新 / 取消」：更新调用桌面壳自己的更新流程（`window.dshDesktop.updates.open()`），面板自身不会弹出任何窗口；取消只是收起这张卡片，下次检查再出现。Web 端没有原生更新器，退化为打开下载页。卡片上另有一个 GitHub 发布页链接，方便手动下载。
- **npm 插件**：调用插件管理器的 `listVersions`，用与插件管理器相同的源和兼容性检查读取新版本。
- **GitHub 插件**：对从 Git 仓库安装的插件，向 GitHub 查询最新发布标签（没有发布时退回标签列表），把标签解析成完整 commit，再与已安装版本比较。

## 更新

「更新」按钮调用插件管理器的 `updateBundle`，pnpm、兼容性检查、失败回滚和重启结论都由插件管理器负责。npm 插件更新到指定的新版本；GitHub 插件更新到固定了目标 commit 的 Git spec。需要重启时页面会说明。

「全部更新」会对每个有更新的插件依次执行同样的操作。

「自动更新」开关打开后，每次检查发现有可更新项就自动执行全部更新；开关状态保存在浏览器本地，默认开启。

应用本体只在桌面端自己报告有更新时才显示新版本（镜像或官方 feed 上出现新版本、但桌面端没有更新时不算），也只有这时才提供「更新」按钮去调用桌面壳的更新入口。自动更新关闭时发现插件可更新，同样会在页面顶部以横幅提示。

顶部横幅显示「发现新版本」和版本变化，带「更新」「知道了」两个按钮；不弹窗，点「更新」才进入桌面壳自己的更新流程。

应用更新开始下载后，顶部横幅会切换成进度样式：标题「正在下载更新」，下一行是版本号和百分比，卡片底边嵌一条 3px 进度条（浅色轨道 + 品牌色填充）。安装 / 启动阶段没有百分比，底边改成来回滚动的动画；结束或失败后横幅消失。

npm 安装的插件行尾还有一个「回退」按钮，展开后列出该插件在镜像上的全部已发布版本（最多 50 个，当前版本会标出来），点「安装」就能切到任意旧版本。回退走「先移除再安装」的路径（pluginManager 的更新接口只接受更新的版本），安装失败时会自动装回原来的版本；GitHub 和本地安装的插件暂不支持回退。

更新需要重启时（host 模块类插件），通知条和批量更新的结果横幅上会出现「重启应用」按钮；侧边栏底部有一个「刷新与重启」下拉，里面是「刷新界面」和「重启应用」。

- **刷新界面**：只重载页面和客户端插件（`location.reload()`），不碰 Host；
- **重启应用**：调用更新中心自己的 `POST /dsh-concierge/restart`，由 Host 用 WMI 创建一个脱离应用进程树的 PowerShell 助手，先杀掉 Electron 主进程、再拉起应用；拉起失败会自动重试 3 次，过程写到 `~/.dsh/update-center/restart.log`。不再依赖 dsh-desktop-restart。

批量更新（自动更新或「全部更新」）完成后，页面顶部会弹出一条结果横幅：逐行列出插件的版本变化和「已更新 / 失败」，并提示重启 DSH 后生效；点「知道了」关闭。横幅挂在 frame 级浮层上，关掉设置页后仍然保留，直到手动关闭。

单个插件更新后同样走顶部弹窗：需要重启时标题是「更新完成，需要重启」，右侧「重启应用」；只需要刷新时标题是「更新完成」，右侧「刷新界面」。副行都是插件名和版本变化，不想现在动就点「知道了」。

## GitHub 来源（可添加多个）

插件页顶部有一张「GitHub 来源」卡片：输入 `owner/repo` 或完整 GitHub 地址点「添加」，可以加多个。每个来源会持续检测 GitHub 上的最新 release（没有 release 时退回 tags）：

- 未安装的显示「最新 x.y.z · 未安装」，可以点「安装」；
- 已安装的显示「最新 · 已装版本」，有新版本时标「有更新」，可以点「重新安装」；
- 每行都有「移除」，只移除监控项，不会卸载插件。

来源列表存在 `~/.dsh/update-center/github-sources.json`。

有些插件是分步骤安装的（装完还要重启、去设置里配置、再重启验证，比如 `XRH66/dsh-memory-starter`）。每个来源行有一个「步骤」按钮：读仓库 README 里「快速开始 / 安装」章节的编号步骤，展开成清单，并附「重启应用」和「打开仓库」两个按钮；从来源行安装成功后会自动展开。

## 从 Git 安装

插件页顶部有一个输入框：填 GitHub 仓库地址（`https://github.com/owner/repo` 或 `github:owner/repo`）就能装。安装时会把仓库 HEAD 解析成完整 commit 再交给插件管理器，这样装出来的插件是「固定 commit 的 Git 安装」，之后能被更新检测和回退识别。装完自动出现在插件列表里，参与后续的检测与更新。

Git 插件走「GitHub releases（没有 release 时退回 tags）→ 下载 → 安装」的流程：更新调用 `updateBundle` 并带上固定 commit 的 spec；如果管理器因为 spec 形式不一致拒绝，会自动退回「移除 + 按目标 spec 重装」。回退时会列出仓库里最多 100 个 tag，按版本号排序。

## 本地插件

本地安装（`link:` / `file:`）的插件没有 registry，也没有 release feed，所以直接看源：

- 源是目录时，读它的 `package.json` 版本，比已装版本新就提示重装；
- 源是 Git 仓库时，记录当前提交；提交或版本变化时提示重装；
- `link:` 安装的代码本来就实时生效，只做提示，不提示重装；
- 源是压缩包（`.tgz`）时，读取包内 `package.json` 的版本；同时记录文件大小和修改时间，压缩包被替换时提示「源压缩包已更新」，可以一键重装（重装走「移除 + 按原 spec 安装」）。

## 安装与卸载

- **从 npm 安装**：插件页有一张卡片，填包名（`dsh-pet`）或包名加版本（`dsh-pet@0.4.9`）就能装。
- **卸载**：每个插件行尾有「卸载」，点一次变成「确认卸载？」再点才真的卸；维护中心自己那行没有卸载按钮。
- **忽略此版本**：不想升某个版本时点「忽略此版本」，之后显示「已忽略 x.y.z」，可以随时「取消忽略」；忽略记录存在浏览器本地。
- **更新内容**：GitHub 安装的插件如果有 release 说明，行上会多一个「更新内容」按钮，展开就是这段说明。
- **错误诊断**：安装/卸载失败时，常见的插件管理器错误码（`invalid-spec`、`incompatible-version`、`pendingBuilds`、`not-removable`、`bundle-in-use` 等）会直接翻成中文提示和下一步动作。

## 安全模式

如果某个插件损坏、应用起不来，插件本身也没机会运行——所以本插件在启动时会把几个脚本写到 `~/.dsh/update-center/`：

- **`safe-mode.cmd`**：双击后先把 profile 的 `package.json` 和 `cordis.patch.yml` 备份到 `safe-backup/`，再把 `dsh.profile.bundles` 过滤成只留官方插件（`@deepseek-ai/*`），然后启动应用；
- **`restore-mode.cmd`**：应用退出后双击，恢复备份并重启；
- **`safe-launch.cmd`**：**自动版**——启动应用后观察 30 秒，如果进程没活下来就判定启动失败，自动备份、切到安全模式再重启一次；启动正常则什么都不做。

把桌面快捷方式指向 `safe-launch.cmd`，以后应用起不来会自动落到安全模式，不用手动判断。

`safe-launch` 同时负责**自动恢复**：连续两次观察到启动正常后，自动把备份的插件配置放回去并重启一次（连续两次恢复失败后停止自动尝试；手动 `restore-mode` 会清零计数）。

「工具」页最上面的「安全」卡片里有一个 **自动安全模式** 开关（存在 `~/.dsh/update-center/settings.json` 的 `safeModeAuto`，默认开）：开着时 `safe-launch.cmd` 会观察 30 秒并在失败时自动切安全模式；关掉后它只负责启动应用，不再自动切。开关一变，脚本会立刻重写，不需要重启。

所有脚本都要求应用已完全退出，不需要管理员权限；`.ps1` 带 UTF-8 BOM，Windows PowerShell 5.1 读中文不会乱码。

## GitHub Token

更新页可以填一个 GitHub token（`ghp_…` / `github_pat_…`），存在 `~/.dsh/update-center/settings.json`：

- 不带 token：GitHub API 每小时 60 次（按 IP），几条 GitHub 来源就够用完；
- 带 token：每小时 5000 次（按账号）。

只读公开仓库的 token 就够（classic 全不勾权限，或 fine-grained 只给 public repo 读）。环境变量 `GITHUB_TOKEN` / `GH_TOKEN` 优先级更高，设了环境变量时页面里的输入会被覆盖。保存后立即生效，不用重启。

## 后台检查

客户端插件常驻，每 10 分钟检查一次更新；发现可更新插件时在顶部弹一条「发现 N 个插件更新」，一小时内最多提示一次，点「知道了」收起。

## 插件启停与回退

每个插件行尾除了「更新 / 回退」，还有「启用 / 禁用」：禁用走 pluginManager 的 `setPluginEnabled`，立即生效（个别插件需要重启）。npm 插件可以回退到镜像上的任意历史版本（最多 100 个）；GitHub 安装的插件可以回退到仓库里的任意 tag；本地目录或压缩包装的插件没有可回退的版本。

如果上次更新后某个插件加载失败，Host 会在下次启动时把它禁用；页面顶部会提示「有 N 个插件加载失败被禁用」并给出「全部启用」。

插件页右上角有「打开插件目录」和「打开配置」，直接打开 profile 的 `node_modules` 和 `cordis.patch.yml`。

## 聊天性能

统计四项：帧率（5 秒平均，显示为「当前 / 屏幕刷新率」——上限由屏幕刷新率决定，自动识别 60/75/90/100/120/144/165/240，也可以在「刷新率」一行手动指定）、消息行数、最近 10 秒的长任务次数与累计阻塞毫秒，外加最近 80 秒的长任务条形历史和峰值。四个开关：

- **自动降级**：平均帧率连续 2 秒低于刷新率的 75% 时，给 `<html>` 加 `data-dsh-perf="low"`，关掉聊天区的动画、过渡、`backdrop-filter` 和阴影；连续 3 秒高于 90% 恢复。
- **长对话精简**：消息行超过 60 条时加 `data-dsh-perf="long"`，关掉聊天流里的动画和过渡。
- **强制精简**：不看帧率，始终按精简模式走。
- **启动加速**：把应用目录、`~/.dsh`、插件目录加进 Windows Defender 排除项。宿主没有管理员权限，所以打开开关时它会写一个脚本并请求 UAC 提权执行，结果回写到 `~/.dsh/update-center/startup-boost.json`，页面轮询这个文件显示状态。
- **屏幕外行跳过**：默认关。只在消息行超过 40 条时启用；按每行的**真实高度**写 `contain-intrinsic-size: auto <height>px`（不是固定占位），只处理真正在屏幕外的行，并在空闲时间分片扫描。Chromium 上 `content-visibility` 有已知的重绘和滚动抖动问题，聊天本身已经虚拟化了行，所以默认不开，长对话明显卡顿时再打开。

另外，检测到聊天正在流式输出（`[data-phase="active"]`）时会临时关掉聊天区的 `backdrop-filter`，流式结束自动恢复。


## 打字机

页面底部还有一张「打字机」卡片：「逐字显示」开关、**流式节流**开关和速度滑杆（10–240 字/秒）。

- **逐字显示**：默认关。它包装内置的 `assistant-step` 渲染器，只把流式中的那段文字按字符预算逐字显示，思考、工具调用、图片保持原样；内层渲染最多每 50ms 提交一次，低帧率时自动让位。
- **流式节流**：默认开。流式输出时，把应用「每个 token 一次」的渲染合并成每 80ms 一次提交。Markdown 每 token 重新解析一遍是流式聊天闪烁的主因，节流能把重绘次数降到十分之一左右，肉眼几乎看不出延迟。

## 限制

- 不会从本页替换应用本体。
- 未在 Host 环境设置 `GITHUB_TOKEN` 或 `GH_TOKEN` 时，GitHub 请求是匿名的，受 GitHub 匿名速率限制。
- 从本地目录或压缩包安装的插件只列出，不检查更新。
- 结果缓存 5 分钟；「检查更新」会跳过缓存。
